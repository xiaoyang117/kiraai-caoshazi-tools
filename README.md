# KiraAI 草傻子工具

> 插件 ID：`intimacy_progress`　|　适用版本：KiraAI ≥ 2.14

在亲密 / 性爱角色扮演中，把「当前进行到哪一步」写进 AI 的上下文，并给 AI 一组工具让它能主动控制节奏。目标是让剧情**自然地推进**——该慢的时候慢下来，该往前走的时候往前走，而不是原地打转，也不是一口气跳到结局。

---

## 它解决什么问题

和 AI 玩这类角色扮演，常见的两个毛病：

- **原地打转** —— 一直停在暧昧或前戏，迟迟不往下走，反复写同一套东西
- **一步到底** —— 铺垫还没做够，AI 直接跳到结局，中间的过程全没了

根因是 AI 不知道「现在到哪一步了」，只能凭上下文猜。这个插件把进度明确告诉它，并让它能主动改变进度。

---

## 特性

| 能力 | 说明 |
|---|---|
| **进度追踪** | 多阶段序列 + 本阶段轮次 + 场景总轮次，按会话隔离 |
| **阶段可自定义** | 内置 6 阶段（试探 → 升温 → 前戏 → 结合 → 高潮 → 余韵）。侧边栏可直接改名 / ↑↓ 调序 / 增删 / 恢复内置 |
| **进度注入** | 把阶段、轮次、进度条写进系统提示词，让 AI 感知 |
| **阶段写作指引** | 每个阶段附带节奏与侧重点参考 |
| **强制每轮回报** | 要求 AI 每轮先汇报进度，再写正文 |
| **主动告知工具** | 即使当前没有场景，也先告诉 AI 它可以自己开启 |
| **自动推进** | 在某个阶段停留过久自动进下一阶段，防止卡死 |
| **兴奋度** | 额外的 0–100 维度，插件自动增长，也可授权 AI 主动调节 |
| **主动收尾** | 进入最后阶段后逐步加压，催 AI 写出结尾并结束场景 |
| **分部位统计** | AI 在收尾时汇报各部位次数，跨场次累计 |
| **场景配图** | 每个回合自动用 KiraAI 自带的生图模型生成一张配图，可调每回合张数 |
| **生效范围可控** | NTR 模式（所有人）或白名单（指定 QQ 号 / 群号 / 昵称） |
| **关键词识别** | 命中关键词自动进出场景，词库可自定义 |
| **侧边栏面板** | 「配置」与「运行状态」双标签页 |

> 所有开关**默认全关**，需要用哪个再打开。

## 安装

1. 把 `intimacy_progress` 整个文件夹放进 KiraAI 的 `data/plugins/` 目录
2. 重启 KiraAI（或在插件管理里启用）
3. 打开侧边栏的插件面板开始配置

```
data/plugins/intimacy_progress/
├── main.py          # 插件主体
├── manifest.json    # 元信息
├── schema.json      # 配置项定义
└── web/
    └── index.html   # 侧边栏页面
```

首次加载时，KiraAI 会按 `schema.json` 生成一份配置（全部默认关闭）。

---

## 快速开始

**最小可用配置**（四步）：

1. 打开 **启用插件**
2. 打开 **向 AI 注入进度**
3. 打开 **主动告知 AI 工具的存在** —— 不开这一项，AI 不知道它有能力主动开启场景
4. 设定生效范围：
   - 打开 **NTR 模式** → 对所有人都生效
   - 关闭 **NTR 模式** → 只服务 **用户白名单** 里填的账号（留空则谁都不生效）

若关闭了 NTR，记得在 **用户白名单** 里填 QQ 号（也支持群号或昵称，一行一个）。

**想要确定性触发**（不依赖 AI 自觉），再打开 **关键词识别场景**，之后消息里出现「摸」「亲」等词就会自动进入场景。

## 配置项

### 基础

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 关 | 总开关 |
| NTR 模式（对所有人生效） | 关 | 打开 = 对所有人生效，白名单被忽略；关闭 = 仅白名单可用 |
| 用户白名单 | 空 | 填 QQ 号 / 群号 / 昵称，可多个。仅在 NTR 关闭时生效，留空表示谁都不生效 |
| 日志详细程度 | 仅关键事件 | 仅关键事件 / 详细调试 |

### 场景识别

| 配置 | 默认 | 说明 |
|---|---|---|
| 关键词识别场景 | 关 | 根据消息关键词自动进入 / 退出场景。关闭后只能由 AI 主动开启 |
| 入场关键词 | 内置词库 | 留空用内置；填写后覆盖内置，命中任一即进入 |
| 离场关键词 | 内置词库 | 命中即退出场景并清空进度 |

### 进度注入

| 配置 | 默认 | 说明 |
|---|---|---|
| 向 AI 注入进度 | 关 | 把当前阶段、轮次、进度条写进系统提示词 |
| 注入阶段写作指引 | 关 | 为每个阶段附带写作指引（需先开「向 AI 注入进度」） |
| 强制每轮回报进度 | 关 | 每轮要求 AI 先调用 `int_report` 回报，再写正文（需先开注入） |
| 主动告知 AI 工具的存在 | 关 | 当前没有场景时也介绍这套能力，让 AI 知道可以主动开启（需先开注入） |

### 节奏控制

| 配置 | 默认 | 说明 |
|---|---|---|
| 自动推进进度 | 关 | 在某个阶段停留过久时自动进下一阶段 |
| 自动推进阈值（轮） | 3 | 停留多少轮后触发自动推进 |
| 场景超时（分钟） | 0 | 超过该时长无消息则视为结束，设为 0 表示永不超时 |
| 追踪兴奋度 | 关 | 额外维护一个 0–100 的兴奋度数值 |
| 允许 AI 控制兴奋度 | 关 | 把 `int_desire` 提供给 AI（需先开「追踪兴奋度」） |
| 允许 AI 主动重置 | 关 | 把 `int_reset` 提供给 AI，让它能自己结束场景 |
| 让 AI 更主动收尾 | 关 | 进入最后阶段后随停留轮数升级催促（需先开「允许 AI 主动重置」） |

### 分部位统计

| 配置 | 默认 | 说明 |
|---|---|---|
| 统计分部位次数 | 关 | AI 在场景收尾时汇报各部位次数，侧边栏按用户累计展示 |
| 部位列表 | 内置 10 个 | 工具提示与统计使用的部位名。留空用内置 |

### 自定义阶段

| 配置 | 默认 | 说明 |
|---|---|---|
| 自定义阶段名称 | 内置 6 阶段 | 可直接编辑当前生效的序列：改名 / 调序 / 增删 / 恢复内置。至少需要 2 个阶段 |

### 场景配图

| 配置 | 默认 | 说明 |
|---|---|---|
| 亲密场景中主动配图 | 关 | 打开后，AI 在亲密场景里**每个回合都会**用 KiraAI 自带的生图模型（`<img>` 标签）生成配图并自动发给对方（需先开「向 AI 注入进度」，并在 KiraAI 设置里配好默认生图模型） |
| 每回合最多生成几张图 | 1 | 一个回合（用户发一次消息）内最多发出多少张配图。**设为 1 就是「每回合一张」**；调大则允许一次多画几张 |

**工作原理**：插件在每个回合注入「本回合还剩几张额度」的明确要求，AI 据此用 `<img>` 标签输出画面描述。

由于生图由 AI 输出标签触发、且在 XML 解析阶段就已完成，插件**无法在生成前拦截**，也无法在 AI 漏画时替它补（画面描述只有 AI 知道）。
因此在解析后加了一道兜底：**超出额度的图会被丢弃**，避免刷屏。

> 如果发现 AI 偶尔不画，那是模型没有遵守提示词——可以在 KiraAI 里换一个指令遵循更好的模型。

> 前提：先在 **KiraAI 设置**里配置一个默认生图模型（`default_image`）。
> 如果没配，启用后插件会在启动日志里给出警告，AI 也无法画出图。

## AI 可调用的工具

| 工具 | 作用 | 需要的开关 |
|---|---|---|
| `int_advance` | 推进到下一阶段；当前没有场景时调用即开启一段新场景 | — |
| `int_retreat` | 退回上一阶段 | — |
| `int_status` | 查看当前进度 | — |
| `int_report` | 回报本轮进度 | 强制每轮回报 |
| `int_desire` | 直接增减兴奋度（正数升温、负数降温） | 允许 AI 控制兴奋度 |
| `int_part` | 记录部位次数（收尾时汇报本场累计） | 统计分部位次数 |
| `int_reset` | 结束并重置场景 | 允许 AI 主动重置 |

未打开对应开关的工具不会出现在 AI 的工具列表里。

## 侧边栏

**配置**标签页

- 全部配置项，按分组排列
- 开关之间有依赖关系：上级开关没打开时，下级项会置灰
- 「自定义阶段」区域可直接编辑阶段序列

**运行状态**标签页

- 统计卡：生效对象、自动推进、场景超时、部位总次数
- 活跃场景表：会话、阶段、进度条、兴奋度、阶段轮次、部位次数、空闲时间
  - 单条可执行「推进 / 退回 / 结束」
  - 可一键「结束所有场景」（**分部位统计会保留**）
- 阶段序列可视化：当前处在整条序列的第几段
- 分部位统计卡片：按用户展示各部位累计次数，可单独清空某个用户的记录

## 工作方式

插件挂在 KiraAI 的两个事件上，并注册一组工具：

1. **消息批次事件** —— 识别场景的进入 / 退出，累计轮次，更新兴奋度
2. **LLM 请求事件** —— 在请求发出前，把当前进度块注入系统提示词
3. **工具调用** —— AI 通过工具主动推进 / 退回 / 调整，插件据此更新状态
4. **XML 解析后事件** —— 统计本回合生成的配图数量，超出额度则丢弃（兜底防刷）

进度状态按会话（`adapter:session_type:session_id`）隔离，不同会话互不影响。

几点行为说明：

- **配置修改立即生效**，不需要重启（保存后热重载）
- **分部位统计是跨场次的档案**，重置场景不会清空它；要清空请用侧边栏的「清空记录」
- **进度只在「进度注入」打开时才对 AI 可见**；否则进度只存在于侧边栏
